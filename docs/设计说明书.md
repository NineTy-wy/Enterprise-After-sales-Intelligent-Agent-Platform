# 售后智能支持平台设计说明书

## 1. 项目定位

本项目面向企业售后支持团队，提供知识资产管理、文档智能索引、售后工单协同和可追溯 Agent 问答能力。

系统的完整业务链路如下：

```text
用户登录
  -> 创建知识库
  -> 上传售后资料
  -> 对象存储
  -> RabbitMQ 异步任务
  -> PDF/Word/Excel/CSV 解析
  -> Chunk 切分
  -> Embedding 向量化
  -> Qdrant 检索
  -> Agent 查询改写 / Hybrid Search / Rerank / 上下文压缩
  -> LLM 生成带引用答案
  -> 工具调用创建工单
  -> AI 评估记录与审计日志
```

## 2. 系统架构

### 2.1 服务划分

| 模块 | 技术 | 主要职责 |
| --- | --- | --- |
| `backend-spring` | Spring Boot 3、Java 21 | 用户认证、多租户、知识库、文档元数据、工单、审计、工具权限、文件上传 |
| `agent-service` | FastAPI、Python 3.12 | 文档解析、RAG、Agent 编排、LLM、Embedding、评估 |
| `frontend-web` | React、TypeScript、Vite | 登录、知识库运营、文档上传、工单操作、问答工作台 |
| PostgreSQL | PostgreSQL 16 | 业务数据、用户、知识库、文档、工单、审计 |
| Redis | Redis 7 | Agent 问答短缓存和后续会话扩展 |
| RabbitMQ | RabbitMQ 3 | 文档解析和索引异步任务 |
| MinIO | S3 兼容对象存储 | 原始文件持久化 |
| Qdrant | Qdrant 1.x | 向量索引和租户过滤检索 |
| Nginx | Nginx | 前端静态资源和 `/api` 反向代理 |

### 2.2 请求链路

普通业务请求由前端访问 Spring Boot：

```text
Browser -> Nginx -> Spring Boot -> PostgreSQL / MinIO / RabbitMQ
```

Agent 问答链路由 Spring Boot 统一鉴权和租户校验，再调用 FastAPI：

```text
Browser -> Nginx -> Spring Boot
                    -> 敏感信息过滤
                    -> 知识库归属和状态校验
                    -> FastAPI Agent
                         -> 查询改写
                         -> Qdrant + 词法召回
                         -> Rerank
                         -> 上下文压缩
                         -> LangChain LLM 或本地降级
                    -> 引用和执行轨迹
```

文档入库链路采用异步处理：

```text
上传文件 -> MinIO
        -> documents: UPLOADED
        -> RabbitMQ document.processing
        -> Agent: PROCESSING
        -> 解析 / Chunk / Embedding / Qdrant
        -> documents: INDEXED 或 FAILED
```

## 3. 关键设计

### 3.1 分层与依赖方向

Spring Boot 按以下边界组织代码：

```text
api                 HTTP Controller 和 DTO
application         应用服务、用例编排、端口接口
domain              领域对象、状态机、仓储接口
infrastructure      PostgreSQL、MinIO、RabbitMQ、内存实现
common              统一响应、异常、当前用户上下文
security             JWT、密码加密、接口保护
```

业务层依赖仓储接口，不直接依赖 JPA、MinIO 或 RabbitMQ。这样本地开发可以使用内存实现，Docker 环境再切换到 PostgreSQL、MinIO 和 RabbitMQ。

### 3.2 多租户隔离

所有核心业务表显式保存 `tenant_id`。每次读取资源时都执行租户过滤：

- 知识库详情按 `tenant_id + knowledgeBaseId` 校验。
- 文档列表先验证知识库归属。
- 工单和审计日志按当前租户查询。
- Agent 检索在向量 payload 和查询过滤器中同时带入 `tenantId`。
- 问答入口拒绝不属于当前租户的知识库 ID。

### 3.3 文档状态机

```text
UPLOADED -> PROCESSING -> INDEXED
                    \-> FAILED -> PROCESSING
```

不允许已索引文档回退到处理中，也不允许已归档知识库继续上传文档。状态冲突统一映射为业务错误码 `40900`。

### 3.4 Agent 编排

`react` 模式和 `plan_execute` 模式共享检索与生成组件，但保留不同的执行轨迹：

- ReAct：观察问题 -> 检索 -> 生成可追溯答案。
- Plan & Execute：Planner 拆解任务 -> Retrieval Agent 检索 -> Answer Agent 生成。
- Tool Calling：工具必须先通过白名单注册，再由 Spring Boot 执行创建工单或查询工单。

### 3.5 降级策略

系统在外部依赖不可用时仍保持可解释行为：

- 未配置 LLM 时使用本地降级回答。
- LLM 请求失败时返回 `fallbackUsed=true`。
- Embedding API 失败时回退到确定性 Hash Embedding。
- Qdrant 不可用时回退到进程内 Hybrid Store。
- Redis 不可用时回退到进程内 TTL 缓存。
- RabbitMQ 未启用时使用本地异步线程池。
- Agent 服务不可用时 Spring Boot 返回人工处理提示。

## 6. 环境配置策略

代码已经提供两种运行模式：

### 本地模式

- Spring Boot 默认 `local` Profile。
- 内存仓储和本地文件存储。
- 本地异步线程池。
- Mock Agent。
- 适合先验证业务代码，不依赖数据库和模型密钥。

### Docker 模式

- PostgreSQL 持久化业务数据。
- MinIO 保存上传文件。
- RabbitMQ 执行异步文档任务。
- Qdrant 保存向量。
- Redis 保存短缓存。
- Spring Boot 通过 HTTP 调用 FastAPI。
- Nginx 对外提供统一访问入口。

需要配置的内容集中在 `deploy/.env`：

- 数据库、RabbitMQ、MinIO 密码。
- `JWT_SECRET`。
- `AGENT_SERVICE_TOKEN`。
- `APP_SECURITY_ENABLED`。
- `LLM_PROVIDER`、`LLM_API_KEY` 和模型名称。
- `EMBEDDING_PROVIDER`、`EMBEDDING_DIMENSIONS`。
